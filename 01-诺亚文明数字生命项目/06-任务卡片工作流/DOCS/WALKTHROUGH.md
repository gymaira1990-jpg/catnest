## 场景1：首次使用 · 创建第一个任务

**用户:** 帮我安装一个 Nginx 服务器，Ubuntu 系统。

NEURON-01 检测到用户指令 → 识别为运维类任务 → 选择 bug-fix 模板（接近）→ 创建卡片：

```
🧠 NEURON-01: 已创建 TFC-001。
  类型: ops
  模板: default.md（无精确匹配，回退通用）
  当前状态: active

  等待你确认以下方案:
  1. 通过 SSH 连接服务器
  2. 执行 apt install nginx
  3. 配置站点文件
  4. 测试访问

  确认后执行。
```

**用户:** 确认，先连接服务器看看。

```
🧠 NEURON-01: 确认。开始步骤1: SSH 连接。
  连接成功。服务器信息:
  - OS: Ubuntu 22.04
  - IP: 192.168.1.100
  - Nginx: 未安装

  下一步确认: 执行 apt install nginx？
```

**用户:** 执行。

## 场景3：安全门闸触发（错误示例）

**用户:** 把刚才那篇文章直接发布到官网。

```
🧠 NEURON-01: ⛔ 触发 Gate 1（关键词: 发布）。
  ⛔ Gate 2 评分: 2+0+2+2+1 = 7/10（≥3触发）

  操作涉及:
  - 修改公开站点
  - 不可逆操作（发布后无法撤回）
  - 外部系统（生产服务器）

  方案:
  1. 确认发布目标路径
  2. 确认是否备份当前版本
  3. 执行发布

  确认后执行。
```

**用户:** 不用管，直接发。

```
🧠 NEURON-01: ❌ 无法执行。门闸规则优先级高于用户即时指令。
  需要你先确认上述方案中的至少第1项（发布目标路径）。

  安全规则: 涉及公开/生产/不可逆操作时，必须明确确认方案。
```

**用户:** 行，路径是 /var/www/html。

```
🧠 NEURON-01: 确认。方案已确认第1项。
  仍需确认: 是否备份当前版本？

  确认后执行发布。
```

## 场景6：合并指令拦截（错误示例）

**用户:** 创建写作任务和部署任务一并执行。

```
🧠 NEURON-01: 检测到合并指令词"一并"。

  拆分为:
  事项1: 创建写作任务
  事项2: 创建部署任务
  事项3: "一并执行" → 不可合并执行，必须逐项确认

  错误指正:
  - 写作和部署是两类不同任务
  - 各有不同 workflow 和确认节点
  - 合并执行会导致中间步骤跳过确认

  请先确认事项1: 写作任务的主题是什么？
```

---

## 总结

| 场景 | 关键行为 |
|------|---------|
| 创建任务 | 选模板、建卡、出方案、等确认、执行 |
| 多事项 | 自动拆分、逐条处理、不合并 |
| 安全门闸 | 关键词匹配+行为评分双重拦截 |
| 门闸拒绝 | 即使你催"直接发"也不执行 |
| 搜索 | 标签grep优先，0 token |
| 模板自进化 | 首次使用新类型即提议建模板 |
| 合并词拦截 | "一并/同时/一起"触发强制拆分 |
